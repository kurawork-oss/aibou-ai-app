# 手元のパソコンで動く相棒

AIbou（ブラウザの中）からは、パソコンの中のファイルを読めません。
読めないのが正しい仕組みです——読めたら、**どのウェブサイトからでも**
読めることになるので。

なので「Obsidianの日誌に足しておいて」「あのフォルダの資料を読んで」は、
Webだけではどうやっても届きません。この小さなプログラムが橋になります。

```
このプログラム ──(外向きに)──▶ AIbouのサーバー「仕事ある？」
                ◀───────────  「これを読んで」
                ──────────▶  「読んだ。中身はこれ」
```

**外向きの通信しかしません。** ルーターの設定も、ポート開放も要りません。

---

## 1. 合言葉をもらう

AIbou を開いて **設定 → つなぐ →「手元のパソコン」→「合言葉を作る」**。
**その台の名前**（「しごとのノート」「家のデスクトップ」など）を先に決めます。

出た文字列を控えてください。**この1回しか表示されません**
（サーバーには照合用の形でしか残っていないので、見せようがありません）。
無くしたら、その台だけ作り直します。

### 何台でも繋げます

ノートPCとデスクトップを**両方繋いだまま**にできます。台ごとに別の合言葉で、
2台目を足しても1台目は切れません（`もう1台つなぐ`）。
スマホには要りません——ブラウザだけで動きます。

2台以上動いているときは、**名前で頼み先を指してください**。

    「しごとのノートの ~/AIbou を見て」

名前を言わなかったときは、勝手に選ばずに聞き返します。ファイルは台ごとに
違うので、黙って選ぶと「ノートを読んだつもりがデスクトップだった」が
起きます。読み違いは気づきにくく、書き違いは取り返しがつきません。

## 2. 用意

```bash
pip install requests
pip install pillow      # 画面を撮るときだけ
```

## 3. 動かす

```bash
python aibou_local.py \
  --url   https://あなたのAPI.onrender.com \
  --token 控えた合言葉 \
  --dir   ~/AIbou
```

`--dir` に渡したフォルダの中**だけ**を触ります。何度でも指定できます。

Obsidian の日誌に書き足したいときは、vault の場所も渡します:

```bash
python aibou_local.py --url … --token … \
  --dir ~/AIbou \
  --vault ~/Documents/MyVault --daily 日誌
```

動き出すと、こう出ます:

```
[10:22:41] 相棒を始めます。触ってよいのは:
[10:22:41]   /Users/you/AIbou
[10:22:41]   Obsidian: /Users/you/Documents/MyVault / 日誌
[10:22:41]   開く: 切  画面: 切
[10:22:41] 止めるときは Ctrl-C。
```

AIbou 側の **設定 → つなぐ** に「繋がっています」と出れば成功です。

## 何をどこまで許すか

| | 既定 | 入れ方 |
|---|---|---|
| 一覧・読む・書く・書き足す | **入** | — |
| ファイルを既定のアプリで開く | 切 | `--allow-open` |
| 画面を撮る | 切 | `--allow-screen` |
| **あなたのブラウザを動かす** | 切 | `--allow-browser` ＋ `--site`（下記） |
| 消す | **無し** | ——（作っていません） |
| 好きなコマンドを実行する | **無し** | ——（作っていません。OpenCLIを使うときも、決まった命令だけ） |

### 守っていること

1. **`--dir` の外は触りません。** `メモ/../../.ssh/id_rsa` のような指定は、
   文字列のままだと「メモの中」に見えます。実際の道に直してから比べるので、
   シンボリックリンクで外へ出る手も通りません。
2. **消しません。** 上書きするときは、元の内容を `.bak` に残します。
3. **隠しファイルは一覧に出しません。**
4. **大きいファイルは読みません**（1MBまで）。読んだ物はAIへ渡るので。
5. **したことは全部出ます。** `--log したこと.txt` を付ければファイルにも残ります。

### なぜこう分けてあるか

サーバーが乗っ取られても、ここから先はこの決まりに縛られます。
サーバーは「読んで」と頼めるだけで、**どこを読めるかは決められません**。
どこまで許すかを決めるのは、このプログラムを動かしているあなたです。

## あなたのブラウザを動かす

AIbou のサーバー側にもブラウザはありますが、**誰にもログインしていません**。
社内ツール・管理画面・会員サイトのように、ログインの先にある物はそこからは
見えません。ここが、手元で動かす意味のある所です。

```bash
# ① 一度だけ、自分でログインする（パスワードはAIbouに渡しません）
python aibou_local.py --url … --token … --dir ~/AIbou \
  --allow-browser --site kintone.example.co.jp \
  --login https://kintone.example.co.jp/

# ② ふだんは、こう動かす
python aibou_local.py --url … --token … --dir ~/AIbou \
  --allow-browser --site kintone.example.co.jp
```

### `--site` は必須です

`--allow-browser` だけでは動きません。**「どこを開かれても構わないか」では
なく「この2つなら構う」を先に決めてもらいます。**

開くのはあなたがログイン済みのブラウザなので、会話に紛れ込んだ一文が
どこかを開かせたら、その先は**あなたとして**操作されることになります。
だから「全部」という書き方は用意していません。

`--site example.com` は `www.example.com` も含みますが、
`notexample.com` や `example.com.evil.jp` は**含みません**（点で区切って
見ています）。

### 見る／触るは、別の扱い

| | AIbou 側の扱い |
|---|---|
| 開いて読む | 中身がAIへ渡るので、確認モードのときは聞きます |
| 押す・打ち込む | **設定に関わらず、必ず聞きます**。「いつも許可」も出しません |

押した先が「送信」かもしれず、そのときは**あなたとして**送られます。
何が起きるかはページ次第でこちらから見分けられないので、重いほうに
倒してあります。

### 2つのブラウザを、役割で使い分けます

| | 向いている仕事 | ログイン |
|---|---|---|
| **あなたのChrome（OpenCLI）** | AIが画面を見ながら判断して操作する | ふだんのChromeのまま |
| **専用ブラウザ（Playwright）** | 決まった手順を毎回同じに流す／OpenCLIが無いときの代わり | `--login` で一度通す |

OpenCLI が入っていれば、AIが判断して動かす仕事は**あなたのChrome**で動きます。
ログインはもう済んでいるので、社内ツールでも開けばそのまま中にいます。

```bash
# OpenCLI を入れる（Node.js 20.18.1 以上）
npm install -g @jackwener/opencli
# Chrome に拡張機能を入れる（Chrome ウェブストアで「OpenCLI」）
opencli doctor        # 繋がっているか確かめる
```

入れていない・Chromeに繋がっていないときは、止まらずに**専用ブラウザ**で
続けます——そして結果に「専用ブラウザで開きました」と出します（ログイン状態が
違うので、黙って替えると結果の読み方を間違えます）。

エンジンを決め打ちしたいときは `--browser-engine opencli` / `playwright`。
決め打ちしたものが使えないときは、**黙って替えずに**理由を返します。

#### OpenCLI を使うときに知っておいてほしいこと

OpenCLI の拡張機能は、**Chromeの全サイトに届く権限**を持っています
（`debugger`・`cookies`・`<all_urls>`）。つまり「このサイトだけ」は
拡張機能の力の限界ではなく、**この相棒が守る決まり**になります。
そのために:

- **開く前に**URLを `--site` と照らします
- **動いたあとにも**、いまどのサイトにいるかを見ます。押したボタンの先が
  許可の外だったら、**そこで止めて**、続きの操作も読み取りもしません
- OpenCLI に渡す命令は**決まった物だけ**です（開く・読む・押す・入力・選ぶ・
  キー・待つ・閉じる）。次の物は**渡しません**:
  - `eval`（任意のJavaScript）
  - `upload`（手元のファイルをページへ送れる）
  - `bind`（**いま見ているタブを乗っ取る**。こちらが開いていないので許可の
    確認を素通りする）
  - `network`（通信の中身を読める）
- OpenCLI には、APIの鍵やトークンらしい環境変数を**渡しません**
- シェルを通さず、決まった形で1つずつ呼びます

専用ブラウザのほうは、許可の外への移動を**読み込む前に**止められます
（OpenCLI では先回りできないので、あちらは「動いたあとに気づいて止める」）。

### 決まった手順を保存して、毎回同じに流す

一度うまくいった操作は、名前を付けて残せます（会話で「この手順を『朝の
ケース確認』として保存して」、または押したあとに出る「この手順を保存」）。
次からは「朝のケース確認を流して」で、**その通りに**流します。
AIが1手ずつ考えないので速く、毎回同じ押し方になります。

- 流すのは**専用ブラウザ（Playwright）だけ**です。あなたのChrome（OpenCLI）
  では流しません——開いているタブの状態に左右されず、毎回同じ所から始める
  ためです。専用ブラウザが要るので `pip install playwright` と
  `playwright install chromium` を済ませてください
- **1手でも失敗したら、そこで止めます。** 続きは押しません（途中がずれたまま
  押し進めると、違う物を送りえます）。何手目で止まったかを返します
- 変わる所だけ `{顧客名}` のように空けておけます。流すときに値を聞きます
- **パスワードは手順に入れられません。** パスワード・暗証番号・認証コード
  らしい欄に打ち込む手順は、保存の時点で断ります。専用ブラウザは、名前が
  普通でも欄そのものがパスワード用（`type=password` など）なら打ち込みません。
  ログインは `--login` で一度だけ、ご自身の手で通してください
- 押す・打ち込む手順は、**流す前に必ず確認します**（あなたとして押すので）。
  確認には、流す手順そのものが出ます

古い相棒（この機能より前の `aibou_local.py`）は手順を流せません。AIbou 側が
「新しくしてください」と言います。

### そのほか

- ブラウザの**画面は出します**（`--headless` で消せます）。何をしているかが
  見えていること自体が安全装置なので、ふだんは出したままをおすすめします
- 一度開いたブラウザは**開いたまま**使い回します。頼むたびに開き直すと
  数秒かかるうえ、ログインのセッションが切れます
- ログイン状態は `--browser-profile`（既定 `~/.aibou-browser`）に残ります。
  消したいときはそのフォルダを削除してください
- 中のJavaScriptを走らせる口（`evaluate`）は**出していません**
- ダウンロードは受け取りません

---

## 止める

`Ctrl-C` で止まります。止めているあいだ、AIbou 側は
「手元の相棒が動いていません」と出ます（黙って失敗はしません）。

合言葉そのものを無効にしたいときは、AIbou の
**設定 → つなぐ →「手元のパソコン」→「繋ぎを切る」**。
